iter65 — THE GRADED-FRAME PER-ROW WALL CENSUS (the frame the 2 s cap is charged in)
==================================================================================
Why this instrument exists
--------------------------
Every wall/cap number in this lane's record came from one of two places:
  (a) the probe frame (`cargo test --release`, `target/probe/release/deps/...`), which is a
      *different binary* — the whole `SSI_*` seam layer and every timing instrument in this
      candidate is `#[cfg(test)]`-gated (src/ordering/mod.rs:5441 `#[cfg(test)] let class_nnz`,
      :5466 `#[cfg(test)] let exchange_ledger`, window_dp.rs:100 `#[cfg(test)] struct WorkReport`),
      so in the production binary they are compiled out; or
  (b) the official local run, which prints `(capped)` instead of a time (src/main.rs:417).
The cap is charged per matrix, on wall clock, on a *child process*
(src/watchdog.rs:85 `let start = Instant::now()` … :111 `start.elapsed() > cfg.time_cap`),
and the grader runs each matrix twice in fresh processes (src/main.rs:339), so a per-row wall
census of the production worker is the only honest cap instrument.

Method (reproducible)
---------------------
  1. `corpus/dev/patterns.jsonl` -> 300 raw pattern files
     (`.scratch/widthcensus/extract.py`, the `ssi-worker-protocol` layout: n, col_ptr, row_idx).
  2. One run per row of the *production* worker `target/release/ssi-candidate-worker`,
     `taskset -c 0-3`, `/usr/bin/time -f "%e %P"` (`.scratch/widthcensus/census.sh`).
  3. Per-row wall + CPU% -> `.scratch/widthcensus/census<tag>.tsv`.
The census is single-run per row: row-to-row jitter is ~0.02-0.05 s, so only deltas above that
are read as signal; the *max* row and the *ordering* are stable across repeats.
