walks the window's live components smallest-first, so a fixed ledger buys the cheap
components the call actually adopts. Control and device in the official frame, same tree
(2 GiB, 45 000, 12 sweeps, pool), one run each:

    results.tsv:1789314683   alloc 0   0.790288 / 0.923150   wall 281.0 s
    results.tsv:1789315062   alloc 2   0.790282 / 0.923147   wall 284.2 s

Exactly **one** dev row moves (crudeoil_lee1_07 0.746 -> 0.744); the crown 4-core census is
unchanged (`0270-crown-4core-s12.tsv`, max 1.04 s either way). So the ledger's "dead zone"
— the unfunded-component spend the hypothesis targeted — is worth **6e-6 dev**. It is kept
in the tree (it is a strict improvement and wall-neutral) but it cannot carry a bat.
Verdict: the hypothesis is real and priced, and it is too small to matter.
