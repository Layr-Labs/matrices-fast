Independent reversed and high-degree MCS roots after the complete frontier

Base and scope

This revision starts at official 386b89bbb808261f2a5b1c02ef4af5749faf6387, whose hidden score is 0.860113. The public control is built from that exact source in an isolated directory with the audited candidate-worker build script and a separately built trusted parent. Its full 300-matrix score is 0.829057. This baseline already incorporates the earlier Codex shared-budget promotion 007ff60 and the subsequent residual-core improvements, small-order cleanup, terminal perfect-elimination-order extraction, and eight-round strict-gain chain. Those improvements are retained. The new work is entirely under src/ordering; manifests, dependencies, corpus, scoring harness, worker interface and sandbox configuration are unchanged.

The existing terminal extractor starts maximum-cardinality search from the first vertex of the incumbent and varies adjacency traversal in two directions. Its eight-round chain stops as soon as neither variation improves the exact objective. That stopping condition does not say that another initial root would also fail. This revision explores that remaining choice after the entire inherited chain has finished, so it cannot alter any earlier search seed, residual-core selection, cleanup credit allocation or inherited chain result.

Implementation

A sibling entry point in peo_extract.rs reconstructs the finished incumbent's chordal completion using the existing checked reconstruction routine. It uses two new seed orders: the reversed incumbent, and a copy of the incumbent whose first vertex is swapped with a maximum-degree vertex of the reconstructed completion. Maximum-degree ties use incumbent position, with the greater position winning; that choice is explicit and deterministic. The latter seed changes just the first root choice and preserves the relative seed order of all vertices other than the swapped pair. Each seed is passed through both existing adjacency traversal directions, producing four MCS orderings. The original two-candidate entry point remains untouched for all inherited callers.

All four outputs are checked as bijections. The caller scores them with the inherited exact reusable symbolic scorer and accepts only a strict decrease relative to the complete incumbent. It can repeat this independent stage for at most four rounds. A round with no strict decrease ends the stage immediately. The finished incumbent is the seed for the next round, and every reconstruction scratch allocation is released before moving to that round. No candidate can be accepted merely because it has a better proxy or a different ordering with equal flops.

The independent stage uses the existing full-graph eligibility limits: n from 16 through 30000 inclusive and at most 180000 input nonzeros. Reconstruction retains the existing 300000 nnz(L) cap, validates every reconstructed column against exact symbolic column counts, and checks its final total. No cap is raised. No clock, environment variable, file, matrix name, persistent cache, random seed or cross-call state is consulted. The selected graph's degree and incumbent positions are the only extra inputs to root selection.

Correctness and objective preservation

Maximum-cardinality search produces a reverse perfect elimination ordering on a chordal graph. The reconstructed graph is the incumbent's elimination completion. Reordering the original graph with a PEO of that completion cannot require fill outside the completion: the later-neighbor cliques already exist there. This gives a structural reason for the candidate family, but the implementation still obtains fresh exact scores on the original pattern and uses a strict comparison. It does not substitute MCS weights for symbolic flop counts.

The existing exhaustive extractor test enumerates all labeled simple graphs on one through five vertices and every incumbent permutation. For each case it independently constructs the filled graph and verifies the reconstruction edge by edge. This revision extends its seed family to cover both adjacency directions for the incumbent, the reversed incumbent, and the maximum-degree seed. Every resulting ordering must be a PEO of the explicit filled graph and must not exceed the incumbent's vendor-backed exact flop score on the original graph. Invalid-input tests and all other existing tests remain in place. The selected revision passes 68 active tests; 20 research probes are ignored by the ordinary suite.

Preserving the full frontier result before the new stage is important. Replacing a seed inside the inherited chain could select a different improving path and lose one of its later gains. Appending this stage provides a direct monotonicity argument relative to the completed frontier ordering on every matrix where execution finishes, not merely relative to AMD. The exact incumbent score is recomputed from the current symbolic column counts at the beginning of each new round, because earlier inherited stages may update the permutation without updating an older score variable.

Limits and prior history

This change adds bounded graph work; it is not a runtime optimization. Each MCS traversal uses linear work and storage in the reconstructed completion, and the maximum new chain length is four. Degree-root selection adds one linear scan and one swap. The full graph is reconstructed once per new round and shared among that round's four MCS traversals. There is no additional fill-edge watcher call and no increase to its shared eight-million-credit allowance. The cap and early break bound work, but only an official successful evaluation establishes the hidden deadline for this submitted revision.
